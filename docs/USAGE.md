# Руководство пользователя

## Подключение

Параметры SSH-сервера включают адрес, порт, пользователя и способ входа:

- **SSH-agent** использует ключи запущенного агента.
- **Ключ** читает выбранный файл; для зашифрованного ключа приложение запросит парольную фразу.
- **Пароль** запрашивается при подключении.

Jump-хосты соединяются сверху вниз, затем устанавливается подключение к конечному серверу. У каждого узла свои параметры входа и проверка ключа.

При первом подключении сравните SHA-256-отпечаток с полученным от администратора сервера. При изменении ключа КРОТ покажет прежний и новый отпечатки и потребует отдельного подтверждения. Отложенный запрос остаётся у туннеля; остальные соединения продолжают работать.

## Режимы туннеля

| Режим | Пример |
| --- | --- |
| **L** — локальный | Открыть `127.0.0.1:15432` для доступа к базе `127.0.0.1:5432` со стороны SSH-сервера. |
| **R** — удалённый | Открыть порт на SSH-сервере для доступа к сервису на вашем компьютере. |
| **D** — динамический | Создать SOCKS5-прокси на `127.0.0.1:1080` и указать его в клиентском приложении. |

Статус «работает» означает, что SSH-соединение установлено и порт открыт. Доступность конечного сервиса проверяется при обращении к нему. Для удалённого прослушивания SSH-сервер должен разрешать выбранный bind-адрес и перенаправление портов.

## Управление

| Клавиша | Действие |
| --- | --- |
| ↑ / ↓ | Выбрать туннель |
| Space | Запустить, остановить или отменить подключение |
| Enter | Открыть ожидающий запрос туннеля |
| N / E | Создать / изменить туннель |
| L / Delete | Открыть журнал / удалить туннель |
| S | Настройки |
| ? / F1 | Справка |
| Q | Меню выхода |
| Tab / Shift+Tab | Перейти между полями формы |
| Ctrl+S / Ctrl+Enter | Сохранить форму |
| Esc | Назад / отмена |

В настройках доступны тема, анимация, заставка и автозапуск после входа в систему.

## Фон и трей

SSH-соединения обслуживает отдельный фоновый процесс. Закрытие окна оставляет их работать. Значок трея показывает состояние: зелёная отметка — работающие туннели, жёлтая — подключение или ожидание ответа, красная — ошибка. Подсказка и меню содержат счётчики.

Левый клик или пункт «Открыть КРОТ» возвращает окно. «Остановить КРОТ» закрывает окно, слушающие порты и SSH-соединения. На Windows счётчики открытого контекстного меню обновляются после его закрытия.

Без поддержки StatusNotifierItem на Linux значок может быть недоступен. Управлять приложением можно из окна и через `krot-cli`.

Автозапуск управляется настройкой окна или командами:

```sh
krot-cli autostart enable
krot-cli autostart disable
krot-cli autostart status
```

Если для восстановления нужен пароль или проверка ключа, туннель дождётся открытия окна. После полного завершения процесса пароли потребуется ввести заново.

## Конфигурация

По умолчанию используется:

- Windows: `%APPDATA%\krot\config.json`.
- Linux: `$XDG_CONFIG_HOME/krot/config.json`, а если переменная не задана — `~/.config/krot/config.json`.

Команда `krot-cli path` показывает выбранный путь. Для отдельной конфигурации передайте `--config <файл>` окну или CLI. `list` и `check` не запускают SSH.

[Пример конфигурации](../examples/tunnels.json) содержит выключенный локальный туннель с вымышленным адресом. Замените параметры перед подключением.

Формат JSON имеет версию 1. Изменения записываются атомарно; размер конфигурации ограничен 2 МиБ. Перед ручным редактированием остановите КРОТ, чтобы работающий процесс не перезаписал изменения.

Рядом с файлом конфигурации хранятся:

| Файл | Назначение |
| --- | --- |
| `config.json.known_hosts.json` | Доверенные ключи SSH-узлов |
| `config.json.desktop.json` | Предпочтение уведомления о работе в фоне |
| `config.json.updates.json` | Номер пропущенного обновления |
| `config.json.background.json` | Служебные параметры локального подключения к процессу |

Служебные файлы и файлы блокировок не нужно редактировать или публиковать. Пароли и разблокированные ключи хранятся в памяти фонового процесса до остановки туннеля. При переносе конфигурации на другой компьютер проверьте пути закрытых ключей.

## Обновления

Фоновая проверка при открытии окна обращается к последнему стабильному релизу GitHub. Если новой версии нет или сеть недоступна, работа продолжается без уведомления.

Для ручной проверки откройте **Справка → Проверить обновление**. Проверка проходит
в фоне. Если новой версии нет, появится сообщение «Обновлений нет»; при ошибке
соединения — предложение проверить сеть и повторить попытку. Для найденной версии
показываются её номер и кнопки «Обновить» и «Позже». Ручная проверка также находит
ранее пропущенную версию и не меняет сохранённый выбор.

- **Обновить** — скачать и установить предложенную версию.
- **Пропустить версию** — больше не предлагать этот номер. Следующая версия снова будет предложена.
- **Позже** — оставить обновление для следующего запуска.

Установщику нужны оба бинарника и право записи в каталог приложения. Он проверяет размер и SHA-256 скачанных файлов, штатно завершает КРОТ, создаёт резервные копии и запускает новую версию. Резервные копии сохраняются до подтверждения готовности окна и фонового процесса. При ошибке замены или раннем сбое запуска выполняется откат. Если откату мешает работающий процесс, КРОТ сохраняет копии и показывает инструкции.

Конфигурация и доверенные SSH-ключи при обновлении сохраняются. На Windows после установки может остаться каталог `.krot-update-*` с копией работающего установщика.

Для ручного обновления полностью остановите прежний КРОТ, распакуйте оба бинарника новой версии и запустите приложение. Повышение привилегий установщик не запрашивает.
