# Безопасность

Исправления безопасности выпускаются для последней стабильной версии КРОТа.

## Сообщить об уязвимости

Используйте [приватное сообщение об уязвимости на GitHub](https://github.com/Dudod1n/KPOT/security/advisories/new). Укажите версию, ОС, шаги воспроизведения и возможные последствия. Для примеров используйте тестовые серверы и вымышленные учётные данные.

Если приватная форма недоступна, откройте issue с просьбой предоставить приватный канал связи, без подробностей эксплуатации. Пароли, закрытые ключи, токены и пользовательские конфигурации в публичные обсуждения не добавляйте.

## Работа с данными

Пароли и разблокированные ключи остаются в памяти фонового процесса, пока нужны туннелю. На диск сохраняются параметры подключения и подтверждённые ключи SSH-узлов. Поэтому конфигурация может содержать имена серверов, пользователей и пути файлов, даже если в ней нет паролей.

КРОТ проверяет ключи SSH-узлов. Новый отпечаток нужно сверять с доверенным источником; изменённый ключ требует отдельного подтверждения.

Локальное управление фоновым процессом использует loopback-соединение с проверкой владения токеном. Проверка обновлений обращается к GitHub, а загрузка начинается после согласия пользователя. Размеры и SHA-256 файлов сверяются перед установкой.

## Перехват трафика приложений (Windows)

Перехват выполняет отдельный процесс КРОТа с правами администратора; он запускается только по кнопке и после подтверждения Windows. От фонового процесса он получает список путей исполняемых файлов и адреса SOCKS5-портов туннелей и ничего не запускает по его указанию. Перехватываются процессы того же сеанса Windows; службы и процессы других пользователей не затрагиваются.

Помощник загружает только `WinDivert.dll` и `WinDivert64.sys` с закреплёнными в коде SHA-256 официальной сборки 2.2.2. Если файлов нет, окно КРОТа скачивает их из релиза своей версии на GitHub и записывает только после совпадения размера и SHA-256 обоих файлов. Каталог КРОТа доступен на запись пользователю, поэтому подтверждение запроса Windows означает доверие к файлам в этом каталоге, как и при запуске самого `krot.exe`.

Пока помощник работает, он принимает перехваченные соединения на отдельном порту и открывает для него входящее правило брандмауэра `KROT-app-relay`. Соединения, которых нет в таблице перехвата, сразу закрываются. Через туннель идёт только TCP; имена разрешает этот компьютер, поэтому DNS-запросы приложения туннель не скрывает. Без запущенного помощника правила не действуют и приложения ходят в сеть напрямую.

## UDP через сервер

Для UDP приложений КРОТ загружает на SSH-сервер собственный помощник `krot-relay` и запускает его через exec-канал SSH. Это происходит только для туннелей, где пользователь явно согласился; выбор хранится в `<конфигурация>.udp.json`.

- Бинарники помощника для Linux x86_64 и aarch64 встроены в КРОТ при сборке вместе с их SHA-256. Хэш проверяется на сервере после загрузки и перед каждым запуском; файл лежит в `~/.cache/krot` с правами `0700`, каталог-ссылка или чужой каталог отвергаются. Между проверкой и запуском файл может подменить только тот, кто уже может писать в каталог `0700` этого пользователя.
- Команды на сервере — фиксированные скрипты `/bin/sh`; в аргументах только хэши, секретов в командной строке и журналах нет.
- Помощник принимает данные только из своего stdin, не слушает портов, не исполняет команд и не пишет на диск. При закрытии SSH-канала он завершается и закрывает все сокеты. Содержимое датаграмм не попадает в журналы и метрики; адреса назначения пишутся только в журнал правила, как для TCP.
- Помощник даёт пользователю UDP-выход с сервера с его же правами. Это сопоставимо с `direct-tcpip`, но работает и там, где администратор сервера запретил переадресацию портов (`AllowTcpForwarding no`). Об этом сказано в тексте согласия.
- Для UDP открывается отдельное SSH-соединение. Оно не задаёт вопросов пользователю: принимает только уже подтверждённый ключ узла и переиспользует пароль или разблокированный ключ из памяти фонового процесса.
- Помощник перехвата получает UDP-канал к фоновому процессу через тот же loopback-порт и ту же проверку токена, что и остальное локальное управление.

Контрольная сумма позволяет обнаружить изменение файла относительно опубликованного значения. Она не заменяет проверку источника загрузки и цифровую подпись издателя. Windows-сборки пока не подписаны.
