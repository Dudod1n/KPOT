## Claude Code

Описание PR завершай строкой `🤖 Generated with [Claude Code](https://claude.com/claude-code)` без ссылки на сессию.

### Ревью кода

Ревью идёт по правилам [REVIEW.md](REVIEW.md). Здесь описано только то, какими командами и в какой сессии его выполнять.

Порядок работы в ветке: написать код → `/simplify` → тесты → черновик PR в `dev` → независимое ревью с inline-комментариями → исправления с ответами → «Ready for review».

- `/simplify` запускай сам в рабочей сессии после того, как код заработал, и до push. Команда не ищет ошибки, а убирает дублирование и лишнюю сложность в изменённом коде.
- Своё изменение в рабочей сессии не ревьюй: ревью должно быть независимым. После создания черновика PR запусти отдельную сессию с командой `/code-review <уровень> <номер PR> --comment`. Если среда этого не позволяет, попроси пользователя запустить команду в новой сессии. Уровень: `low` для изменений низкого риска, `medium` или `high` для остальных.
- В сессии ревью публикуй находки inline-комментариями в PR: приоритет P0–P2, сценарий и доказательство. Раунд завершай итоговым комментарием в обсуждении PR с BASE, HEAD, результатом и статусом замечаний.
- В рабочей сессии каждый inline-комментарий разбирай отдельно: исправь код, закоммить и отправь в ветку PR, затем ответь в ветке этого комментария. В ответе укажи, что сделано, и SHA коммита. Если исправлять не нужно, ответь с обоснованием. Без ответа не оставляй ни один комментарий. Ветки обсуждений не закрывай, это делает пользователь.
- Для подтверждённых замечаний P0/P1 до исправления заведи задачу «Исправления по ревью» по [docs/WORKFLOW.md](docs/WORKFLOW.md). После исправлений нужен новый раунд ревью на новом HEAD.
- Флаг `--fix` не используй: он правит код без ответов в PR.
- Когда раунд не нашёл новых P0/P1 и открытых P0/P1 не осталось, предложи пользователю перевести PR в «Ready for review».
- Релизный PR `dev` → `main` сам не ревьюй. Напомни пользователю запустить в новой сессии `/code-review high <номер PR> --comment`, затем `/engineering:code-review` для того же PR. Если релиз затрагивает авторизацию, секреты, сеть или обработку внешнего ввода, предложи добавить `/security-review`.
- Находки релизного ревью исправляй в `dev` через ветку и PR, а не в релизном PR, и отвечай на каждый inline-комментарий в релизном PR по тем же правилам. `/simplify` для релизного PR не применяй.
- Уровни `max` и `ultra` используй только по явной просьбе пользователя. `ultra` платный, его запускает сам пользователь.
