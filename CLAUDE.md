## Claude Code

Описание PR завершай строкой `🤖 Generated with [Claude Code](https://claude.com/claude-code)` без ссылки на сессию.

### Ревью кода

Порядок работы в ветке: написать код → `/simplify` → тесты → PR в `dev` → `/code-review --comment` → исправления с ответами на комментарии.

- `/simplify` запускай сам в рабочей сессии после того, как код заработал, и до создания PR. Команда не ищет ошибки, а убирает дублирование и лишнюю сложность в изменённом коде.
- После создания PR в `dev` запускай сам `/code-review <уровень> <номер PR> --comment`: уровень `medium` или `high`, для мелких правок — `low`. Находки публикуются inline-комментариями в PR.
- Каждый inline-комментарий ревью разбирай отдельно: исправь код, закоммить и отправь в ветку PR, затем ответь в ветке этого комментария. В ответе укажи, что сделано, и SHA коммита. Если исправлять не нужно, ответь с обоснованием. Без ответа не оставляй ни один комментарий. Ветки обсуждений не закрывай, это делает пользователь.
- Флаг `--fix` не используй: он правит код без ответов в PR.
- Релизный PR `dev` → `main` сам не ревьюй. Напомни пользователю запустить в новой сессии `/code-review high <номер PR> --comment`, затем `/engineering:code-review` для того же PR. Если релиз затрагивает авторизацию, секреты, сеть или обработку внешнего ввода, предложи добавить `/security-review`.
- Находки релизного ревью исправляй в `dev` через ветку и PR, а не в релизном PR, и отвечай на каждый inline-комментарий в релизном PR по тем же правилам. `/simplify` для релизного PR не применяй.
- Уровни `max` и `ultra` используй только по явной просьбе пользователя. `ultra` платный, его запускает сам пользователь.
